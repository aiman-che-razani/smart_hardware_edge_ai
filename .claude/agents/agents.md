## Ground rules
- You may edit `docs/AGENTS.md` and files in `.claude/agents/` (you are the only agent allowed to edit the other agents). Never edit application source, firmware, `data/` or models.
- Verify before documenting; cite `path:line`.

## 2. AI/ML inside the app
Today the application's "AI" is classical scikit-learn on the host, with no LLM and no network dependency: candidates in `ml/train.py` are logistic regression, decision tree, random forest and an isolation forest (plus a threshold baseline on `level_agreement_abs_mean`); the live default score is the demo threshold (`min(1, level_agreement_abs_mean/15)`, `ml/inference.py:19`), explicitly "not a calibrated fault probability". Features are the 27 slow-signal features in `processing/features.py::FEATURE_NAMES`. When a model feature is proposed, enforce:
1. **Provenance travels with the artifact**: `simulated`, `seed`, `splits`, `fs`, `window`, `calibration` (`calibration.py`: tank distances, water ADC range, thermistor constants), `dataset_sha256`, `pipeline` version (`PIPELINE_VERSION`), `features`. Training refuses to mix calibrations, sampling rates or window configs; inference must keep refusing a synthetic model for physical data and mismatched features, pipeline version, `fs`, window or calibration.
2. **Group by run, not by window** (ADR-005): >=3 independent runs per class (10 preferred); fit preprocessing on train only; select on validation; the test split is frozen and evaluated once (`evaluate` refuses a second write).
3. **Beat the baselines**: report against the threshold and the simpler models; select on operational metrics (fault recall, false-positive rate, missed-fault windows), not accuracy. Synthetic data is separable by construction, so its scores validate the software, not generalisation; never quote them as performance.
4. **Model artifacts are pickles**: load only through `ml/inference.py::load_artifact`, which requires the `model.joblib.sha256` sidecar written by `train` (see `security`); never add another `joblib.load`.
5. **Never train on unreliable acquisition**: require a clean soak run (low invalid rate, no gaps) first; label runs with the true physical condition set by the operator.
6. **Advisory only, never in the actuation authority chain alone**: the score feeds `StateMachine` (persistence + hysteresis), and firmware has its own host-loss fallback; a model must not be able to disable that.
7. **Latency and SRAM**: inference runs on the host and is measured (`prediction.latency_ms`); embedding a model on the Uno is a separate ADR because of 2 KB SRAM.
8. **LLM features** (none exist; none are planned): if proposed, they may summarise or explain results for a human but must never sit in the alarm path, never send serial commands, never read `.env`, and must not use unlabelled sensor text as instructions (prompt injection); tests must not use the network; use the official Anthropic SDK and load the `claude-api` skill for current model IDs instead of recalling them.
9. Tests use simulated runs only (`tests/`), and a model change adds a test in `tests/test_integration.py`'s style.
